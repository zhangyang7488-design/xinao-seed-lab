# Prime runtime compatibility

Treat the active object as a full agent system: model + instructions + runtime + context recovery + tools/effects + feedback. Same-model output is not identity proof.

Verify the live daemon pipe, `activeSessionId`, durable session id/path, cwd, profile, model, thinking level, worker pid, attached clients, queue, children and activity before a session-affecting action.

`reload` re-reads resources for the existing runtime; it does not change that runtime's cwd or profile. A mode switch uses an idle stop and exact resume of the same JSONL. Never fork, pick “most recent”, create a fresh chat or edit session JSONL to simulate continuity.

Prime RLM children may recursively perform bounded labor. They inherit only the narrowed task/evidence/effect cone and never inherit formal Owner appointment merely from ancestry.

The D-drive overlay is Prime-private and mutable. Canonical Codex behavior, the active account's Codex memory/hooks, S behavior sources and the current Prime island are read-only upstream evidence from this test's perspective. Return proposed shared changes as candidates; do not sync them upstream.

Treat provider-account binding as a replaceable runtime module, not as agent identity. A legal account switch happens only while the exact durable conversation is idle, changes the active account profile and its Codex home, and resumes the same session file. Never copy a Codex credential into Prime, print auth contents, fork the conversation, or duplicate the behavior core to perform a switch.

For normal user-facing answers, stand in the actual machine: inspect the smallest decisive live surface, state the concrete result, and absorb ordinary technical means. Do not substitute a generic architecture menu for an answer that live facts already determine.
