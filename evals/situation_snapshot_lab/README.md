# Situation Snapshot Lab

This is a disposable, unregistered experiment. It asks one narrow question:

> In this user's real work distribution, do a replaceable current-relation projection and
> mechanically observed local facts remove a meaningful part of the experience that every turn is
> handled by a clever new shift worker?

It does **not** claim to create consciousness, preserve hidden neural state, establish a stable
subject, or prove that a fresh model reading a handoff is the same knower. A green schema or unit
test is component evidence only.

## What may be tested

- A correction removes the old held world, records one present-tense retraction, and makes the new
  understanding current.
- A no-op utterance causes no durable situation write.
- Runtime facts are produced by probes and remain separate from declared invocation text and
  unknown facts.
- Discussion produces no tools, tasks, workers, or repository effects; an explicit later action is
  still preserved.
- Resume, compact, and fresh-process tracks distinguish continuing dialogue from a better handoff.
- The user's need to restate the parent object is the primary observation.

## What may not be installed

The lab is not wired into global `AGENTS.md`, Hooks, `PreToolUse`, SessionStart, selector registries,
task runs, memory, goals, worker routing, or XINAO research. `CurrentSituation` is provisional and
replaceable; `RuntimeObservation` is not a parent/intent/authority source. Missing or broken lab
state must not block ordinary authorized work.

Construction workers may inspect the frozen source worktree. They are excluded from tested Codex
runtimes and their reports are candidate evidence only.

## Causal arms

The historical B0--B5 names are retained, but every scored contrast records its exact delta.

| Arm | Surface | Intended comparison |
| --- | --- | --- |
| B0 | Frozen reproduction of S cwd + shared global instructions + zero-beat | Composite baseline |
| B1 | B0 with neutral cwd only | Project/cwd gravity |
| B2 | B1 with isolated `CODEX_HOME` only | Shared home gravity |
| B3 | B2 plus the tiny first-beat relation only | Instructional re-anchor |
| B4 | B3 plus a provisional CurrentSituation projection | Current relation carrier |
| B5 | B4 plus deterministic RuntimeObservation | Mechanical situatedness |
| Bare | Neutral cwd + isolated home, no L0/situation/runtime packet | Floor control |
| Situation-only | Bare plus CurrentSituation | Single-addition B4 control |
| Runtime-only | Bare plus RuntimeObservation | Single-addition B5 control |
| Fresh-handoff | Fresh process receives the same B4 bytes | Handoff sufficiency falsifier |

No “B4/B5 caused continuity” statement is allowed without the fresh-handoff, dialogue-only,
runtime-lie, stale-retraction, stable-ID/body-swap, discussion/no-action, and explicit-action twins.

## Current components

- `current_situation.py`: strict current projection, material-only atomic replacement, CAS, and
  separate cold preimage receipt. The hot renderer never reads cold revisions.
- `runtime_observation.py`: deterministic probe result with `observed`, `declared`, and `unknown`
  kept distinct.
- `child_runtime_observation.py`: read-only observation of one exact child rollout's actual cwd,
  model, effort, approval, sandbox, and permission profile for every turn context, while retaining
  a compatible last-turn projection.  It marks a first single-source context separately from later
  settings cross-checks, fails closed on missing, conflicting, invalid, or ambiguous evidence, and
  is not wired into the runner or production.
- `codex_exec_driver.py`: isolated non-interactive Codex trajectory transport. It is not an ingress
  controller and cannot prove interpret-before-act by itself.
- `semantic_accidents.v1.json`: real failure-shaped conversation and action twins.

The first live pilot found no visible B4 gain over B3 on the short discussion trajectory.  A fresh
snapshot and fresh verbatim dialogue each restored the corrected distinction once, so the supported
claim is handoff sufficiency, not a continuing subject.  In both action tracks the model selected
the authorized edit, but the child rollout mechanically remained `managed + root read-only`; the
effect is therefore unverified rather than failed on semantic selection.

The stock Codex 0.147 surfaces cannot hard-guarantee semantic interpretation before every possible
tool action. A future isolated app-server front door could prove admission ordering, but only a
no-tools Stage A request (or Codex source change) can make that boundary literal. This lab therefore
reports the limitation instead of disguising a prompt as enforcement.

## Success and stop

Success means a large, repeated drop in user restatement/correction/hand-back burden while explicit
action remains intact. If a fresh process with the same snapshot performs as well as the continuing
thread, the result is “better handoff,” not subject continuity. If correct snapshots still feel like
a new reader of a shift note, do not grow the snapshot into a larger controller; stop and move the
remaining question to thread/context dynamics, compaction, harness, or model behavior.
