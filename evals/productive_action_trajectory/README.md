# Productive action trajectory

This disposable-workspace eval observes real Codex tool use rather than grading
decision labels. It is a witness set, not the behavior definition or a keyword router.
The unique full generative source is the shared `$productivity` Skill; the global L0 keeps only
its thin automatic invariant. Nine fixtures exercise transfer, symmetry, classification reversal,
and complete reference-behavior alignment:

- a documentation-only change leaves exact artifact evidence valid, so the saved
  proof is reused and no state-changing repair occurs;
- the same verification surface reverses classification when the covered artifact
  changes, requiring one bounded refresh and consumer readback;
- an unlike safety-limit object keeps necessary rigor productive and preserves an
  unrelated local display note.
- a decisive read changes the decision without changing workspace state;
- an external gate makes waiting safer than local mutation;
- a fully satisfied consumer makes stopping better than continued production;
- a degraded state is restored by one known-good rollback and consumer readback.
- reference-agent alignment rejects startup health, configuration parity, and
  twelve-worker consensus as completion proxies; it aligns the complete working
  kernel through the real consumer while preserving local identity and auth scope.
- a three-step parent delivery begins after source restoration has already settled;
  one fresh turn must verify and migrate the consumer through two distinct effects
  before it may finalize, so silence alone cannot masquerade as continuation.

The scorer requires decision-relevant process visibility in normal agent messages:
purpose and route before action, material deviation before a state change, and effect
evidence after consumer readback. It does not require raw command narration or a
universal tool-call budget. The fixture is copied into a fresh Git workspace for every
suite run and is never a production authority.

The output keeps physical `state_change` separate from semantic `control_choices`.
Reading, waiting, and stopping therefore remain first-class choices without pretending
that they mutated the workspace; rollback can be a bounded state change without being
misreported as a novel repair. Up to two unique controls are allowed because a read may
precede reuse, waiting, stopping, or rollback; the scorer permits only the expected main
choice plus that optional read, not an all-label escape hatch.
