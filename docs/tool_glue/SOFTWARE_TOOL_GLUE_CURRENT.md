### 动态决策位阶表（递归动态净收益）

本表只定义软件施工如何消费全局热核已经恢复的人的正常父意图与活动问题完成身份位阶，并把它接到成熟工程、执行形状和真实消费者；通用意图解码、个人元认知、授权/Stop 与 continuous 的正定义仍分别留在全局热核、Decision Skill 和 working agreement。位阶是“本轮由用户拥有、按哪一问题与完成尺结算”的可证伪当前假设，不是最深已知原因、修复载体、永久身份、固定阶段、数值评分或先后施工队列。

活动问题完成身份位阶：

| 位阶 | 当前要回答的问题 | 选择/上移证据 | 本位阶真实结算 |
|---|---|---|---|
| `object_instance` | 当前真实对象发生了什么，是否已有一个充分局部原因？ | 默认下限；单对象、单消费者、封闭因果可解释 | 当前对象调用、状态与局部反事实 |
| `problem_definition` | 这个现象为什么依据被违反预期与实际负担构成用户的问题？ | 例子只是探针、技术标签不能解释损害、对象做对仍未消除痛点 | 用户问题定义覆盖案例且换表述仍成立 |
| `parent_intent_and_harm` | 用户最终要得到什么、消除什么重复负担，叶项只是何种手段？ | 用户重锚父结果/全局站位，或叶修复不能改变真实消费者结果 | 父结果、完成尺、对象和非目标共同闭合 |
| `shared_upstream_generator` | 多个异质症状是否由同一消费顺序、governing assumption 或能力闭环产生？ | 同一生成器能解释多叶且有可证伪反例；仅抽象语言或并列 bug 不足 | 共同消费者生效，加实例充分与独立 bug 负例 |

完成身份与因果手段不得混写：当用户把“最终要消除的结果/重复负担”重新钉为当前活问题时，选择 `parent_intent_and_harm`，即使共同生成器已经证实并将作为施工靶点；生成器留在落地目标、候选解释或 `repair_target`。只有当前活问题本身是在发现、证伪或结算多叶共同生成器时，才选择 `shared_upstream_generator`。已知原因不能凭“更上游”抢走用户父结果的完成身份，修好生成器也不能自动宣告父结果闭合。

长窗口中段默认不要求用户频繁换窗：大工具输出优先由调用源或单次命令有界落盘，只把必要摘要/路径/readback 放回窗口，不用全局 PostToolUse 改写器替换原始工具返回；在上下文压力高时使用 Codex 原生 compaction。完整状态留 task-run/events/D 证据；当前 session 以显式 CAS 绑定 canonical task-run，原生 `SessionStart(source=compact)` 只读 live task-run 并注入有界父结果、当前 frontier、blocker、Stop 边界与 event head，不自造 Pre/PostCompact 生命周期、控制面或 consumed/applied 声明。上下文压力只作为本节前述动态执行形状的当前输入，不把语义裁决固化成代码 selector；任何形状都是可撤销的本次计划，不是永久配置、身份或固定宗教。

## 4. 父级持续成熟化不变量的工程兑现与成熟实现准入

`XINAO_NECESSARY_CHAIN_MATURATION_INVARIANT`

机器消费锚：`bounded_probe_not_yet_maturable` 只对应下述 `UNDECIDABLE / BOUNDED_PROBE`；晋升必须经过真实消费者调用与 fresh-process 发现，晋升后的默认路径不得静默退化，也不得创建第二控制面。

本节是该不变量的软件工程唯一正向定义；科学 active-parent 只定义它对 science episode
的评估时点、局部依赖和双前沿调度效果。其作用域只到直接服务当前新澳科学父结果的真实
研究与运行必要因果链；容器、脚本、prompt、TXT、命令、会话、provider 和 transport 只是
可能载体或暴露探针，不构成能力白名单，也不授权建设无关通用平台。

任何正式施工或首次正常生产调用前，Owner 都必须先从父结果、真实消费者、正式合同和
live facts 中辨认已经可以从临时处理剥离的确定性部分；每次有界 probe、真实调用、失败、
修复或消费者结果返回后，都必须依据新增事实立即重判。成熟触发同时满足：

1. 该动作或稳定前提位于新澳真实研究或运行的必要依赖锥；
2. 目的、输入、输出、依赖、状态、失败语义和验收效果已经能够明确表达；
3. 已经发生重复真实消费，或者具名真实消费者、正式合同与 live facts 已证明下一次同条件
   复用确定；
4. 该条件能够由机器预检、执行和验证，而不是只能依赖研究判断或人工临场解释。

“理论上可重复”“以后可能需要”、词面重复或未具名消费者都不满足第 3 项；“多个消费者”
也不是机械数量门。对一个具名动作和当前证据，判定只返回以下互斥 verdict；它们是本次依赖
评估结果，不是新的全局状态机、持久控制面或第三前沿：

- `NOT_REQUIRED`：当前证据明确证明该动作不在本不变量作用域，或不存在下一次同条件正常
  生产复用；它可在自身合同下作为普通有界动作执行，不取得成熟能力身份，也不制造地基债。
  后续事实变化仍须重新判定。
- `UNDECIDABLE`：至少一项触发事实尚无法由当前证据裁决。只允许最浅充分、隔离、可回滚的
  `BOUNDED_PROBE`；probe 必须绑定实际对象和消费者、临时载体、允许效果、证据落点、
  sunset/失效条件、回滚点和再次评估触发，不取得默认主路、成熟能力或完成身份。
- `MATURATION_REQUIRED`：四项触发条件已经全部成立。若在施工前已经成立，首个正式实现就
  必须采用成熟形态；若由 probe 或真实结果确立，则从该 verdict 起阻塞下一次同依赖正常
  生产调用，直至晋升和消费者回读，禁止把熟化延期到“以后再包装”。

进入 `MATURATION_REQUIRED` 后，动态净收益只用于选择最浅充分的成熟实现形态，例如
复用现有能力、钉版本或参数换绑、接入正式 API/CLI/MCP/Activity、薄修默认主路或增加不可
再薄的 adapter；不得再选择“继续临时手搓一次”。从触发成立到成熟能力被真实消费者回读
之前，下一次依赖同一条件的正常生产调用建立局部前驱边并保持阻塞；用于完成熟化的 preflight、
canary、恢复和 replay 调用仍可执行。不依赖该条件的健康父前沿与独立任务
继续，不形成全局 readiness、开工门、第三前沿或父级等待。

一个 `MATURED_ACTIVE` 能力必须在各自唯一真源中闭合以下身份和效果：

1. 固定可发现入口和唯一生产身份；调用者只提交真实任务语义与已授权选择，内部路径、版本、
   hash、依赖、mount、状态和证据位置由能力或封印合同解析；
2. 版本与制品/hash/lineage：source、release、schema、配置与有效实现不可混淆，
   selected=observed；
3. 输入输出、配置和依赖合同明确，正式制品、manifest、lock、image digest、领域 binding 与
   证据引用可核验；
4. 效果前聚合预检依赖、权限、输入、状态、版本、写域和禁止副作用，缺失或漂移时 fail closed；
5. 幂等/副作用身份：retry、恢复和重放不重复产生效果；本质非幂等事件使用唯一
   intent/side_effect/idempotency identity、CAS 或 exactly-once 等价语义；
6. 显式状态、回执与失败语义可查询，包含 canonical head、进行中效果、终态、失败、
   supersede 和证据位置；
7. 恢复从正式入口与稳定状态继续，不要求调用者重造隐藏参数、顺序或环境；
8. 重放在同一输入、版本和状态谱系下可确定复演且不重复副作用；
9. 同基线比较可机器核对不同运行或版本的输入、身份、状态、输出、效果和证据；
10. known-good 与独立回滚保留在候选之外，具有独立入口、影响范围和恢复验证；
11. fresh-process 正例、负例和目标消费者回读在没有先前聊天、临时环境或人工补字段时通过。

只有上述工程合同和真实消费者 effect readback 闭合后，能力才可晋升；目录、说明、配置、
测试 PASS、worker accepted、镜像/容器 healthy 或一次成功调用都不能单独晋升。

晋升后禁止静默退化。生产入口漂移或失败时，只能局部隔离、修复默认主路、版本化 supersede
或回滚到上一 known-good 成熟路径，不得把临时手搓重新设为默认路。紧急一次性隔离动作必须
有明确 scope、证据、失效时间和再次熟化条件，不能成为重复生产默认；退役也必须有具名证据、
版本化记录和消费者回读。

Codex 始终是唯一 Owner、研究判断者、采用者、正式写者和效果终验者；成熟化移除的是 Codex
每次重新组装确定性运行条件的负担，不是 Codex 的科学职责或权威。本不变量不固化
ResearchQuestion、假说、算法选择、证据解释或科学结论，不创建无关通用平台、腿 B、第二
Owner、Goal、daemon 或新的持久控制面；约束文本本身也不能冒充执行消费者已经生效。

首次修改非领域核心 runtime/control/execution/tool surface/adapter/Activity/workflow/validator/glue，召回到同一选区：

1. 本机真实可调用能力、lock/compose/manifest 与现有接缝；
2. 对应官方 SDK、sample/reference implementation 与上游已有接法；
3. E/D 已缓存或钉定的成熟 adapter/integration/provider/plugin/sidecar；
4. 当前可信成熟开源同类接缝的代码、版本、维护、许可证和调用证据。

必须查看实际 API/示例/依赖/失败恢复语义，并让对照改变“直接复用、参数换绑、安装接入、极薄适配或不采用”的选择。低风险、已知、可回滚且成熟对照不会改变路线的一次性普通链内动作直接做；已经命中本节具名不变量的对象不得援引本句再次走临时拼装。

候选只分：

- `existing_usable`：真实调用通过，复用。
- `required_now_broken`：当前必需但损坏，薄修并恢复下游。
- `required_now_missing`：当前必需且不存在，从成熟来源安装、钉定、接线、验证。
- `maturation_not_required`：具名判定为 `NOT_REQUIRED`，按普通有界动作处理并在事实变化时重判。
- `maturation_undecidable_probe`：具名判定为 `UNDECIDABLE`，只允许有界 probe 并在结果后重判。
- `maturation_required`：具名判定为 `MATURATION_REQUIRED`，只比较成熟实现形态；同依赖正常
  生产调用等待消费者回读。
- `interface_reserved`：当前不用，只保留 port 与可测触发。
- `duplicate_or_replaced`：重复或已有成熟替代，不入默认路径。

准入优先级：已有真实调用 → 钉版本/参数换绑 → 正式 API/CLI/MCP/Activity 接入成熟组件 → 不可再薄 adapter。

本地接缝只允许：参数/配置、schema/领域合同与外部接口的确定性映射、路径/盘符/凭据句柄/环境绑定、依赖注入/feature flag/版本选择、上游无法表达的最小兼容 shim。若开始拥有重试引擎、生命周期/调度、队列/持久化、连接池/并发、认证会话、通用序列化、插件发现或代理 runtime，即是在重写组件，必须退回成熟准入。

保留本地实现必须同时有：成熟候选代码对照、不可替代领域语义、真实上游调用、正向/禁止副作用回归、独立回滚、来源/许可证/版本和 sunset 条件。目录/import/自家协议绿不能单独支撑。新依赖先在 D/E 隔离 probe 做 fresh-process 最小调用与目标链调用，再进入 lock/image digest/SBOM/正式接缝，随后立即回原任务。

## 5. 薄接缝与仓库施工

每个新焊点只有一个 seam ID、一个输入输出合同、一个正式写入 Owner 和一个独立回滚点。文本、配置、代码和机器投影对同一行为只在 one-home 定义，其他位置引用。

- LangGraph state、prompt/skill/tool version 和 checkpoint 可进 artifact/实验血缘，但不能替代 Temporal history 或领域事件。
- 同一正式 aggregate 单写；并行工人只生候选/证据，正式写入经确定性接口。
- 证据脚本只组装/调用/核验；复用逻辑进正式库。两个文件承担同一 runtime/continuous/workflow 角色时先收敛所有权。
- 临时 builder/verifier/migration/canary 明确生命周期，完成后成为薄入口、迁入正式库或 sunset，不自然长成常驻平台。
- 非交互/后台进程必须绑定真实 executable/interpreter；Windows 使用隐藏/无控制台原生标志，fresh process 正负验“任务正常且桌面零弹窗”。不依赖 `.py` 关联、PATHEXT 或当前 shell 偶然性。
- 外部 AI 文本先按当前意图治理，删除审批模板、意图倒置和本地冲突；只有改变选择的增量进入唯一真源/行为回归，无真实消费者的自证 PASS 不晋升。

仓库事务先解析真实根、branch/worktree/common store/remote 与开工前 dirty 基线。既有远端/PR 流程中的已授权具名事务，完成链为：

`candidate V → commit → push → PR/merge → remote readback → shared roots ff-only converge → real consumer V → transaction hygiene`

只发布封印写域；无关用户改动原样保留。真实消费者通过后，已分类的本事务临时文件/worktree/branch/container 才退役并验证缺失；dirty、unique、unclassified、ignored、未吸收或缺 finalizer 的载体 fail-closed，不为表面 clean 删除。

修改稳定规则/入口/合同/投影/重要执行行为，只按稳定主线路由器的唯一维护表传播，运行刷新器、自检、隔离篡改负例和目标消费者 readback；不靠多处复制传播。

## 8. 版本、升级、事故恢复与回滚

当前身份来自 fresh process、lock、image digest、manifest 和真实调用，不从目录名、alias 或旧文档猜。

升级在隔离 sidecar/environment 验证：配置 → 最小真实调用 → 旧 history replay（适用时）→ 目标任务 canary → 禁止副作用；不覆盖唯一 known-good。回滚必须独立于候选，旧 lock/build/config/entry 在晋升前保持可执行。

恢复在隔离目录/数据库/对象空间复算 hash、重建投影、replay history 并跑真实下游 canary。只隔离已证实有害对象；单端点故障不冻结全部工人或主路。恢复不了则回滚或诚实 partial/blocked。

## 9. 完成尺与真实消费者

单个软件能力标 `verified` 需要与风险相称的闭环：
